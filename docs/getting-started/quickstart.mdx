This quick start launches mAItion with an external Ollama server at
`http://100.85.191.78:11434`. It configures the already-installed `qwen2.5:14b`
model as the default for OpenWebUI and the RAG backend. Files in `./data/input`
are the default knowledge source.

## Requirements

- Docker with Docker Compose
- Network access from the Docker host and containers to `http://100.85.191.78:11434`
- `qwen2.5:14b` installed on that external Ollama server
- Internet access during the first start to download container images and the local embedding model
- One or more documents to index

No OpenAI or OpenRouter API key is required for the default setup.

## 1. Prepare Configuration Files

From the repository root, copy the supplied examples:

```bash
cp .env.rag.example .env.rag
cp .env.openwebui.example .env
cp config.yaml.example config.yaml
```

The examples are ready to run with these defaults:

- Directory source: host `./data/input`, mounted read-only at `/data/input`
- Local embeddings: `sentence-transformers/all-mpnet-base-v2`
- Shared Ollama root URL: `http://100.85.191.78:11434`
- Backend inference: ROAT appends `/v1` internally for its OpenAI-compatible client
- OpenWebUI chat: native Ollama through the same root URL
- Default chat and rephrase model: `qwen2.5:14b`, selected from the models installed on the remote server

Keep `OLLAMA_BASE_URL` as the root URL without `/v1`. Compose supplies that one
value to both OpenWebUI and ROAT.

## 2. Add Documents

Copy documents into `./data/input`. The worker sees that directory as
`/data/input` and scans it recursively once per hour by default.

To use a different host directory, set `DIRECTORY_HOST_PATH` in `.env`. Keep
`DIRECTORY1_PATH=/data/input` in `.env.rag` unless you also change the container
mount target in `compose.yaml`.

## 3. Start the Stack

Run:

```bash
docker compose up -d --build --remove-orphans
```

The ROAT services are built locally from `Dockerfile.roat`; no Docker registry
login is required for a `modified-maition-roat` image.

When upgrading from the local-Ollama stack, `--remove-orphans` removes the old
`ollama` and `ollama-init` containers. The old `ollama_data` volume remains but is
harmless unless you explicitly choose to remove it.

Wait for all services to become healthy:

```bash
docker compose ps
```

The stack does not start an Ollama container or download models. Confirm the
external API is reachable and `qwen2.5:14b` appears in the installed-model list:

```bash
curl http://100.85.191.78:11434/api/tags
```

To use a different model, an administrator must install it on the external Ollama
server before you set `OLLAMA_DEFAULT_MODEL` in `.env`.

OpenWebUI stores provider settings in its persistent volume. For an existing
installation, update its Ollama URL to `http://100.85.191.78:11434` and select
`qwen2.5:14b` in the Admin Panel if the previous local URL remains.

## 4. Log In

Open `http://localhost:3000`.

Use admin credentials from `.env`:

- email: `X_WEBUI_ADMIN_EMAIL`
- password: `X_WEBUI_ADMIN_PASS`

If unchanged, defaults are:

- username: `admin@example123.com`
- password: `q1w2e3r4!`

Change these credentials and `WEBUI_SECRET_KEY` before exposing the service to
other users. The default `WEBUI_BIND_HOST=127.0.0.1` accepts connections only
from the Docker host; set it to `0.0.0.0` only for a trusted network deployment.

## Optional Remote Providers and Sources

OpenRouter/OpenAI-compatible inference and S3 ingestion remain available, but
they are disabled in the default examples. See [Frontend environment
variables](/configuration/frontend-env), [Backend environment
variables](/configuration/backend-env), and the [S3 connector](/connectors/s3-connector)
when you want to opt in.
