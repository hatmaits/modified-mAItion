## What is mAItion?

mAItion is an AI knowledge platform that ingests data from connectors and lets you chat with that data.

## Do I need OpenAI or OpenRouter to start?

No. The default Compose stack connects to external Ollama at
`http://100.85.191.78:11434` and uses the already-installed `qwen2.5:14b` model
for OpenWebUI chat and backend rephrasing. Local embeddings and the Directory
connector also require no hosted API key.

OpenRouter and OpenAI-compatible services are optional alternatives.

## Which Ollama URL should I configure?

Configure the single root URL in `.env`:

```dotenv
OLLAMA_BASE_URL=http://100.85.191.78:11434
```

Do not append `/v1`. OpenWebUI uses the native Ollama API at this root URL, while
Compose passes the same value to ROAT and ROAT appends `/v1` internally for its
OpenAI-compatible client.

## How do I verify the external Ollama server?

Query its installed-model endpoint from the Docker host:

```bash
curl http://100.85.191.78:11434/api/tags
```

The default `qwen2.5:14b` was selected from the models already installed on this
server. The Compose stack does not run Ollama or pull models.

When upgrading from the former local-Ollama stack, run:

```bash
docker compose up -d --build --remove-orphans
```

This removes the old `ollama` and `ollama-init` containers. The old `ollama_data`
volume remains harmless unless you explicitly remove it.

## Why do I not see my documents in answers yet?

Most common causes:

- connector is not configured
- ingestion schedule did not run yet
- the host directory is empty or mounted at the wrong path
- source credentials are wrong for an optional remote connector

For the default setup, place files in `./data/input`, keep
`DIRECTORY1_PATH=/data/input`, and check `docker compose logs celery_worker`.

## How often does data refresh?

Per connector schedule. Configure schedule env vars (in seconds), for example:

- `DIRECTORY1_SCHEDULES` (default: `3600`)
- `S3_ACCOUNT1_SCHEDULES`
- `MEDIAWIKI1_SCHEDULES`
- `SERPAPI1_SCHEDULES`

## Can I use multiple connectors at once?

Yes. You can enable multiple source types and multiple instances of the same type in `config.yaml`.

## Can I use multiple S3 accounts or buckets?

Yes. S3 is optional. Uncomment an S3 source in `config.yaml`, set its matching
`.env.rag` variables, and add further entries such as `S3_ACCOUNT2_*` when needed.

## What is the difference between frontend and backend env files?

- `.env.openwebui.example`: Frontend runtime and admin bootstrap settings
- `.env.rag.example`: RAG backend API/workers, connectors, rate limits, and provider config

The copied frontend file is named `.env`. It also controls Compose substitutions,
including `DIRECTORY_HOST_PATH`, `OLLAMA_BASE_URL`, and `OLLAMA_DEFAULT_MODEL`.

## How do I change the default Ollama model?

Ask an administrator to install the model on the external Ollama server first.
Then set `OLLAMA_DEFAULT_MODEL` in `.env` and recreate the stack. Compose supplies
that value to OpenWebUI and every RAG service but does not pull it:

```bash
docker compose up -d --force-recreate
```

The RAG services use the new value immediately. OpenWebUI stores provider settings
in its persistent volume, so an existing installation may also need its Ollama
connection set to `http://100.85.191.78:11434` and its global default updated in
the Admin Panel.

## Is `ENABLE_SIGNUP` required?

Keep `ENABLE_SIGNUP=True` on first start for admin auto-provisioning, then disable later for single-user/private mode.

## How can I improve answer quality?

- Keep sources fresh (shorter schedules)
- Use reliable embedding and inference models
- Give the first ingestion run time to finish before testing retrieval
